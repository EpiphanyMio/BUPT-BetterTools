## 0. 数据放在哪：本机为底，云端可选

**默认状态是纯前端**：没有任何服务器接口，数据只在你自己的浏览器里，分两层存：

| 存什么 | 存在哪 | 为什么 |
| --- | --- | --- |
| 工具清单、分组、收藏、排序、各种设置 | **localStorage** | 都是小段 JSON，读写是同步的，简单直接 |
| 文件管理里的文件和文件夹 | **IndexedDB** | 要存二进制、容量大。localStorage 只有约 5MB，而且只能存字符串 |

所以你说的「调接口」，实际调的是这两组东西：

- **一次性读 / 普通函数** —— `src/lib/*.ts`
- **响应式数据（一变界面就自动重渲染）** —— `src/hooks/*.ts` 里的 Hook

**现在多了一个可选的云端同步**（`worker/index.ts` + Cloudflare D1）：
在「通用设置 → 云端同步」里填了令牌之后，上面这层本地存储会和云端来回同步。
没填令牌就完全不联网，行为和以前一模一样 —— 这是刻意的：
**同步是加分项，不是运行前提**，云端挂了网页照样完整可用。

同步的接口契约见第 12 节。

## 1. 数据形状（先看这个）

定义在 `src/types.ts` 和 `src/lib/fileStore.ts`。

### Tool —— 一个工具卡片

```ts
interface Tool {
  id: string          // 唯一标识，收藏 / 排序 / 列表 key 都用它
  name: string
  url: string
  description: string
  category: string    // 所属分组名，比如「开发」
  icon?: string       // emoji，可选
}
```

新增 / 编辑时用的是 `ToolDraft`（不含 id 和 category，由程序补）：

```ts
interface ToolDraft { name: string; url: string; icon: string; description: string }
```

### FileNode —— 一个文件或文件夹

```ts
interface FileNode {
  id: string
  name: string
  kind: 'folder' | 'file'
  parentId: string   // '' 表示根目录。不用 null，因为 IndexedDB 的索引不能索引 null
  size: number
  mime: string
  createdAt: number
  updatedAt: number
}
```

### SearchHit —— 文件搜索的一条结果

```ts
interface SearchHit {
  node: FileNode
  pathNames: string[]   // 所在各级文件夹名，用来显示「它在哪」
}
```

### FileStats

```ts
interface FileStats { fileCount: number; folderCount: number; bytes: number }
```

## 2. localStorage 的键名（**改之前先看这里**）

| 键 | 内容 | 由谁写入 |
| --- | --- | --- |
| `better-tools:tools` | `Tool[]` | `useTools` |
| `better-tools:groups` | `string[]` | `useTools` |
| `better-tools:seed-version` | 数字（字符串形式） | `syncSeedTools` |
| `better-tools:favorites` | `string[]`（工具 id） | `useFavorites` |
| `better-tools:order` | `string[]`（工具 id，按显示顺序） | `useToolOrder` |
| `better-tools:app-settings` | `AppSettings` | `useAppSettings` |
| `better-tools:dev-settings` | `DevSettings` | `useDevSettings` |
| `better-tools:theme` | `'system' \| 'light' \| 'dark'` | `useTheme` |
| `better-tools:sync-token` | 同步令牌（等于密码，**不要提交**） | 设置面板 |
| `better-tools:sync-revision` | 本地记住的云端版本号 | `src/lib/sync.ts` |
| `better-tools:sync-dirty` | 有未上传改动时置 1（防抖那 1.5 秒内关页面不丢改动） | `src/lib/sync.ts` |

> ⚠️ **改键名 = 用户数据丢失**。真要改，必须同时写迁移：读旧键 → 写新键 → 删旧键。
> ⚠️ 改某个对象里**已有字段的类型或含义**也一样危险；**只是新增可选字段**是安全的（读取处都做了默认值兜底）。

## 3. 工具与分组：`useTools()`

```ts
import { useTools } from '../hooks/useTools'
const { tools, groups, addTool, /* ... */ } = useTools()
```

| 返回项 | 类型 | 说明 |
| --- | --- | --- |
| `tools` | `Tool[]` | **用户自定义顺序还没应用**，显示前要按 `useToolOrder` 的 `order` 排一遍 |
| `groups` | `string[]` | 分组名，**数组顺序就是标签顺序** |
| `addGroup(name)` | `void` | 重名自动忽略 |
| `removeGroup(name)` | `void` | ⚠️ **会把组里的工具一起删掉** |
| `reorderGroups(from, to)` | `void` | 拖动标签排序用 |
| `addTool(category, draft)` | `void` | 自动生成 id |
| `updateTool(id, draft)` | `void` | |
| `moveTool(id, category)` | `void` | 换分组 |
| `removeTool(id)` | `void` | |
| `mergeSeed()` | `number` | 把默认清单里缺的补进来，返回补了几个 |
| `missingSeedCount` | `number` | 默认清单里有、本地还没有的个数 |
| `resetAll()` | `void` | ⚠️ 清空成默认清单 |

### 模块级函数（不挂在 Hook 上，可在任意地方调）

| 函数 | 说明 |
| --- | --- |
| `syncSeedTools()` | 应用启动时调用一次，把 `tools.json` 新增的工具补进本地。**必须放在 `App.tsx` 模块顶层**，否则停在首页时不生效 |
| `readTools()` | 读一次工具列表，不订阅变化。给「全局搜索」这种一次性读取用 |
| `readToolCounts()` | `{ toolCount, groupCount }`，给首页显示数字用 |

## 5. 显示顺序：`useToolOrder(allIds)`

```ts
const allIds = useMemo(() => tools.map(t => t.id), [tools])
const { order, setOrder } = useToolOrder(allIds)
```

- `order: string[]` —— 按显示顺序排好的 id 列表
- `setOrder(ids)` —— 拖动排序后写回
- 会**自动对齐**：删掉的工具不留残影，新加的工具排到末尾

**标准写法**（把 `tools` 按 `order` 排一遍）：

```ts
const rank = new Map(order.map((id, i) => [id, i]))
const sorted = [...tools].sort(
  (a, b) => (rank.get(a.id) ?? Infinity) - (rank.get(b.id) ?? Infinity),
)
```

## 6. 设置：`useAppSettings()` 和 `useDevSettings()`

两个 Hook 形状一样，只是存的东西不同：

```ts
const { settings, updateSetting, resetSettings } = useAppSettings()
//     settings.defaultCategory : string   （'全部' 表示不筛选）

const { settings: dev, updateSetting: updateDev } = useDevSettings()
//     dev.dragActivationDistance : number
//     dev.autoScrollEnabled      : boolean
//     dev.autoScrollThreshold    : number
//     dev.autoScrollAcceleration : number
```

新增一个设置项的固定套路：

1. 在对应的 `DEFAULT_*_SETTINGS` 里加默认值
2. 在 `GeneralSettingsPanel.tsx`（或 `DevSettingsContent.tsx`）里加控件
3. 在用到它的组件里读 `settings.xxx`

读取时**都做了默认值兜底**，所以老数据里没有新字段也不会炸。

## 7. 主题：`useTheme()`

```ts
const { mode, setTheme, resolved, systemDark } = useTheme()
```

| 字段 | 说明 |
| --- | --- |
| `mode` | 用户选的**意图**：`'system' \| 'light' \| 'dark'` |
| `setTheme(mode)` | 切换（全局生效，所有调用处同步更新） |
| `resolved` | **实际显示**的深浅：`'light' \| 'dark'` |
| `systemDark` | 系统当前是不是深色 |

全局单例（`useSyncExternalStore` 实现）。组件里**不要**自己判断颜色，
直接用语义类名（`bg-surface` / `text-fg` / `border-line` …），深浅由 CSS 变量自动切。

## 8. 文件管理：`src/lib/fileStore.ts`（**全是异步**）

> 所有函数都返回 `Promise`，调用处必须 `await`。
> 内部用 IndexedDB，两张表：`nodes`（名册）+ `blobs`（内容）。

| 函数 | 返回 | 说明 |
| --- | --- | --- |
| `listChildren(parentId)` | `FileNode[]` | 列某个文件夹里的东西。文件夹在前，再按名称排 |
| `getPath(folderId)` | `FileNode[]` | 从根到该文件夹的整条链路，做面包屑用 |
| `createFolder(name, parentId)` | `FileNode` | |
| `addFile(file, parentId, overrideName?)` | `FileNode` | 名册和内容在同一个事务里写，不会半截 |
| `renameNode(id, name)` | `void` | |
| `deleteNode(id)` | `number` | 删文件夹会连整棵子树一起删，返回删了几个 |
| `deleteNodes(ids)` | `number` | 批量删除 |
| `getBlob(id)` | `Blob \| null` | 取文件内容 |
| `getStats()` | `FileStats` | 总文件数 / 文件夹数 / 总字节 |
| `getQuota()` | `{ usage, quota } \| null` | 浏览器给的占用与上限 |
| `requestPersistentStorage()` | `boolean` | 申请持久化，避免磁盘紧张时被回收 |
| `moveNode(id, targetParentId)` | `'ok' \| 'same' \| 'cycle'` | 拒绝两种非法移动：移到原地、移进自己的子孙 |
| `uniqueName(name, taken)` | `string` | 重名时生成「名字 (2).后缀」 |
| `searchNodes(keyword)` | `SearchHit[]` | **全库**按文件名搜（不只当前文件夹） |

## 9. 打开 / 下载文件：`src/lib/fileActions.ts`

```ts
const ok = await openFileNode(node)      // 新标签页打开；false = 库里找不到内容
const ok = await downloadFileNode(node)  // 触发浏览器下载
```

> 为什么要单独抽出来：`blob:` 地址不能马上 `revokeObjectURL`，
> 新标签页还在按它加载内容，得留 60 秒。这种细节复制两份迟早会改漏一处。

## 11. 加一个新功能，该从哪儿接

| 你想做的 | 从这儿开始 |
| --- | --- |
| 页面上多一个数字 / 统计 | `useTools()`、`getStats()`、`readToolCounts()` |
| 新增一个设置项 | `DEFAULT_*_SETTINGS` → 面板控件 → 读 `settings.xxx` |
| 动工具数据（增删改） | 只用 `useTools()` 暴露的方法，**不要直接改 localStorage** |
| 动文件 | `src/lib/fileStore.ts`，**不要直接开 IndexedDB** |
| 打开 / 下载文件 | `src/lib/fileActions.ts` |
| 加一个工具链接 | 改 `src/data/tools.json`，然后 `SEED_VERSION + 1` |
| 加一个页面模块 | `Home.tsx` 的 `cards` 加一项 → `ModuleId` 加名字 → `App.tsx` 加一条渲染分支 |

**三条底线**

1. **不要绕过 `src/lib` / `src/hooks` 直接读写 localStorage 或 IndexedDB。**
   现在这样写，将来换成后端只要改这两个地方。
2. **不要改已存在的键名或字段含义。** 光顾着代码跑通，用户数据就没了。
3. **文件操作一律 `await`。** IndexedDB 全是异步，忘了 await 会拿到 `undefined`。

## 12. 云端同步接口（HTTP，可选功能）

**这是本项目目前唯一的后端接口。** 实现在 `worker/index.ts`（Cloudflare Worker），
数据存在 D1（SQLite）的 `snapshot` 表里，永远只有一行 —— 整包快照。

### 线上地址

页面：<https://bupt-bettertools.yuesu76.workers.dev/>
接口：`https://bupt-bettertools.yuesu76.workers.dev/api/snapshot`

**同步令牌存在 `scripts/_sync-token.txt`**（`scripts/_*` 已在 .gitignore 里，不会进仓库）。
换设备/换浏览器时，进「通用设置 → 云端同步」把那一串粘进去就行。

> 令牌等于密码：谁拿到它就能读写你全部工具和收藏。**不要发到公开地方，也不要提交进仓库。**
> 想换一串：`node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"` 生成新的，
> 然后 `npx wrangler secret put SYNC_TOKEN` 粘贴，再更新那个文件、并在每台设备上重填。

### 通用约定

| 项 | 值 |
| --- | --- |
| 基址 | 同源 `/api`（线上和页面同一个 Worker，所以**不需要 CORS**） |
| 鉴权 | 每个请求带 `Authorization: Bearer <SYNC_TOKEN>` |
| 令牌来源 | 本地：`.dev.vars`（已 gitignore）；线上：`wrangler secret put SYNC_TOKEN` |
| 响应 | 一律 JSON，且带 `cache-control: no-store` |
| 体积上限 | 请求体 ≤ 256KB，`tools` ≤ 500 条，超了返回 400 |

### GET /api/snapshot —— 读云端现状

```
200 → { revision: number, updatedAt: number, data: SyncData | null }
401 → { error: "unauthorized" }
```

云端从没存过数据时返回 `{ revision: 0, updatedAt: 0, data: null }` ——
**不是 404**，因为客户端靠 `revision === 0` 判断"我这份就是第一版，推上去"。

### PUT /api/snapshot —— 整包覆盖写入

```
body: { baseRevision: number, data: SyncData }

200 → { revision: number, updatedAt: number }
409 → { error: "conflict", snapshot: { revision, updatedAt, data } }
400 → { error: "bad-request", message: string }
401 → { error: "unauthorized" }
```

**乐观锁怎么工作的**（这是整个同步正确性的核心）：

```sql
UPDATE snapshot SET revision = revision + 1, ... WHERE id = 1 AND revision = ?baseRevision
```

`baseRevision` 是"客户端以为云端现在是第几版"。如果别人先写过，这条 UPDATE 一行都匹配不到，
`changes === 0` → 回 409 并把**当前最新快照**一起带回去，客户端据此覆盖本地。

为什么不能"先 SELECT 再 UPDATE"：查完到改之间别的请求可能已经写进去了，
那个空档就是数据被覆盖的地方。把版本号放进 WHERE，判断和写入由数据库一句完成，中间没有缝。

### SyncData

```ts
interface SyncData {
  tools: { id: string; name: string; url: string; description: string; category: string; icon?: string }[]
  groups: string[]
  favorites: string[]
  order: string[]
  appSettings: { defaultCategory: string }
}
```

**不同步**：`devSettings`（调试参数）、`theme`（每台设备的显示偏好）、文件管理里的文件。

### 前端那边怎么用它

| 文件 | 作用 |
| --- | --- |
| `src/lib/sync.ts` | 同步引擎：HTTP、状态机、防抖、revision 记账、离线处理 |
| `src/hooks/useSync.ts` | 把引擎状态接到 React（`useSyncExternalStore`） |
| `src/lib/syncData.ts` | 在 5 个 localStorage 键和 `SyncData` 之间打包/写回 |
| `src/components/SyncSettings.tsx` | 设置面板里的令牌输入与状态显示 |

### 本地怎么跑（不需要 Cloudflare 账号）

```bash
node scripts/_sync-e2e.mjs           # 跑 12 项接口断言后退出
node scripts/_sync-e2e.mjs --serve   # 只起服务（127.0.0.1:8787），给前端联调
```

它用 `node:sqlite` + `node:http` + 直接 import `worker/index.ts`，搭出一个等价环境。
配合 `vite.config.ts` 里的 `/api → 127.0.0.1:8787` 代理，前端代码在生产/开发下是同一行 `fetch("/api/...")`。

> 为什么不用 `wrangler dev`：这台机器上 workerd 建不了自己的临时目录
> （`kj/filesystem CreateDirectory: 拒绝访问`），是环境限制不是代码问题。
> `wrangler deploy --dry-run` 能通过，说明打包和配置本身没问题。
