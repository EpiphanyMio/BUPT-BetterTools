# 个人工具箱项目计划

> 建议文件名：`my-toolbox-plan.md`  
> 用途：记录推荐路线、关键决策和项目记忆，方便后续继续开发。

---

## 0. 项目记忆（简短）

- **目标**：制作一个个人工具箱，聚合各种实用工具和网站，支持跨平台访问。
- **用户情况**：编程初学者，但对计算机使用精通；需要适度详细的代码讲解，以便在制作过程中学习语言；讲解不能过于深入和繁琐，目标是能大致看懂 JS/TS 等代码逻辑。
- **核心结论**：优先做**网页 + PWA**，不要一开始做原生 App。
- **推荐技术栈**：Vite + React + TypeScript + Tailwind CSS + PWA + Vercel / Cloudflare Pages。
- **后期同步**：需要多设备同步时，再接 Supabase 或 Firebase。
- **语言分工**：
  - 前端必需：HTML、CSS、JavaScript、TypeScript。
  - Python：后端、自动化脚本、数据处理、同步服务。
  - C：底层模块、高性能计算、命令行工具、WebAssembly。
- **融入 Python 和 C 的原则**：前端仍是网页技术；Python 和 C 放在后端、脚本、底层模块里，分阶段加入，不要三线并行。
- **部署目标**：得到一个网址，电脑和手机都能访问，可添加到主屏幕，像 App 一样打开。
- **隐私注意**：如果包含私人链接或笔记，要加密码保护或访问控制。
- **讲解风格**：关键代码会解释变量、函数、事件、数据流向，但不深入底层原理和复杂设计模式；目标是能大致看懂，而不是成为专家。

## 1. 总体图景

把整个项目想成“开一家自己的网上工具箱小店”：

1. **写网页**：做页面、搜索框、工具卡片、收藏按钮。
2. **本地预览**：用 Vite 在电脑上开临时网址，边改边看。
3. **打包成品**：把代码加工成浏览器能懂的 HTML、CSS、JS、图片。
4. **存档到 GitHub**：像云存档，改坏了能回退。
5. **自动发布**：连到 Vercel 或 Cloudflare Pages，自动上线并分配网址。
6. **跨平台访问**：电脑浏览器、手机浏览器都能打开。
7. **PWA 加持**：可添加到主屏幕，有图标，能全屏，能离线缓存基础页面。
8. **后期云同步**：接 Supabase 或 Firebase，让收藏和配置多设备同步。

一句话：  
**写网页 → Vite 打包 → GitHub 存档 → Vercel/Cloudflare 发布 → 手机电脑访问 → PWA 像 App → 后期云同步。**

## 4. 分阶段推荐路线

### 阶段 1：纯前端静态工具箱

**目标**：先有一个能访问的跨平台网页。

- 用 Vite + React + TypeScript + Tailwind。
- 工具数据先写死在 JSON 文件里。
- 功能：工具卡片、搜索、分类、收藏、打开链接。
- 收藏存浏览器本地。
- 部署到 Vercel 或 Cloudflare Pages。

**验收**：手机和电脑都能打开网址。

---

### 阶段 2：加入 PWA

**目标**：让网页像 App。

- 加 Manifest。
- 加 Service Worker。
- 配置图标。
- 支持“添加到主屏幕”。
- 缓存基础页面，支持简单离线访问。

**验收**：手机能安装到桌面，打开有图标、全屏显示。

---

### 阶段 3：加入 Python 自动化

**目标**：让 Python 开始参与项目，但不影响网页运行。

- 用 Python 读取书签或配置，生成工具数据 JSON。
- 用 Python 检查网站链接是否失效。
- 用 Python 生成图标、整理分类、去重。
- 用 Python 写部署辅助脚本。

**验收**：改数据、检查链接、生成配置更省事。

---

### 阶段 4：加入 Python 后端与同步

**目标**：手机和电脑能同步收藏和配置。

- 用 FastAPI 写简单 API。
- 用 SQLite 或 PostgreSQL 存数据。
- 提供收藏同步、配置同步。
- 部署到 Render、Railway、Fly.io 等平台。
- 前端通过 API 读写云端数据。

**验收**：手机收藏，电脑也能看到。

---

### 阶段 5：加入 C 模块

**目标**：让 C 参与真实功能。

- 先写 C 命令行工具：哈希、进制转换、文本统计、简单计算器。
- 用 Python 的 ctypes 或 subprocess 调用。
- 后端暴露成 API 给前端。
- 注意限制输入、超时和沙箱，避免安全问题。

**验收**：前端能调用由 C 提供的能力。

---

### 阶段 6：C 编译成 WebAssembly（可选）

**目标**：纯静态部署也能用 C 写的工具。

- 用 Emscripten 把 C 编译成 WASM。
- 前端 JavaScript 直接调用。
- 适合纯计算工具：哈希、校验、压缩、表达式求值。

**验收**：不依赖后端，也能在浏览器运行 C 模块。

## 6. 学习优先级

1. HTML + CSS：知道页面由什么组成。
2. JavaScript：变量、函数、数组、对象、事件。
3. TypeScript：给数据加类型，减少低级错误。
4. React：组件、状态、列表渲染。
5. Git + GitHub：会存档、会推送。
6. 部署：会用 Vercel 或 Cloudflare Pages。
7. PWA：知道 Manifest 和 Service Worker 的作用。
8. Python：脚本、文件处理、FastAPI。
9. C：命令行工具、底层算法、WASM。
10. SQL / Supabase：需要云同步时再学。

学习方式：  
**结合项目代码边做边理解，关键代码会解释变量、函数、事件和数据流向，但不深入底层原理和复杂设计模式。**

---

## 7. 避坑提醒

- 不要一开始做原生 App。
- 不要用 Python 或 C 替代前端。
- 不要一开始就上后端和 WASM。
- 不要把私人链接直接公开。
- 不要一开始就做多设备同步。
- 不要三线并行学 HTML/JS、Python、C。
- 不要为了用 C 而用 C，普通功能用 JS 更简单。
- 不要把 C 命令行程序直接暴露给公网。

## 9. 下一步建议

先只做阶段 1：  
**首页 + 搜索 + 分类 + 收藏 + 部署上线。**

跑通之后，再加 PWA。  
再之后，用 Python 做自动化。  
需要同步时，再加 Python 后端。  
最后再把 C 作为底层模块或 WASM 融进去。

核心节奏：  
**先上线，再变 App，再加 Python，再做同步，最后加 C。**
