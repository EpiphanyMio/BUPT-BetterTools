## ① 数据状态约定（最重要，已落代码）

### 先说结论：五种状态的判定依据

| 状态 | 判据 | 建议长相 |
|---|---|---|
| `loading` | `listLoading === true` | 骨架屏 / 占位块 |
| `ready` | `!listLoading && !listError && items.length > 0` | 正常列表 |
| `empty` | `!listLoading && !listError && items.length === 0` | 空态提示 + 引导操作 |
| `error` | `listError !== ''` | 错误提示 + 重试按钮 |
| `stale` | **文件模块没有这个状态** | 不适用 |

### 我在 `src/modules/FilesModule.tsx` 里加了什么

```ts
const [listLoading, setListLoading] = useState(true)   // 首次就是 true，读完才变 false
const [listError, setListError] = useState('')          // 读取失败的中文提示；空串 = 没失败
```

`refresh()` 里用 `try/catch/finally` 维护它们 —— `finally` 里关 `listLoading`，
这样**即使抛异常也不会永远停在骨架屏**（这是骨架屏最常见的一种 bug）。

## ② auth / sync 的接口形状

### `useAuth()`

```ts
const { status, user, isAdmin, lastError, login, register, logout } = useAuth()

status: 'loading' | 'anonymous' | 'authenticated'
user:   { id: number; username: string; isAdmin: boolean } | null
isAdmin: boolean            // = user?.isAdmin === true
lastError: string           // 中文；空串表示没错误
login(username, password): Promise<AuthUser>
register(username, password, inviteCode): Promise<AuthUser>
logout(): Promise<void>
```

**状态机只三条**：

```
本地没有令牌 ──────────────► anonymous（首帧就是它，不会闪 loading）
本地有令牌 ── 问服务器 ──► loading ── 200 ──► authenticated
                                └── 401 ──► anonymous（并清掉令牌）
```

⚠️ **`loading` 只在"本地有令牌、正在向服务器确认"时出现**。没登录过的人打开页面，
第一帧就是 `anonymous` —— 所以登录页不会先闪一下过渡页，这点已经处理过了。

**登录 / 注册失败不会改 `status`**：函数会 **throw**（错误信息已是中文），同时 `lastError` 也被写上。
所以两种写法都行：

```ts
try { await login(u, p) } catch (err) { setMsg(authErrorMessage(err)) }   // 推荐
// 或者直接读 const { lastError } = useAuth()
```

### `useSync()`

```ts
const { status, revision, lastSyncedAt, lastError, isConfigured, syncNow, setToken } = useSync()

status: 'unauthenticated' | 'unconfigured' | 'idle' | 'syncing' | 'synced' | 'error' | 'offline'
revision: number        // 本地记住的云端版本号
lastSyncedAt: number    // 本机上次同步成功的时间戳；0 = 这次打开还没成功过
lastError: string       // 中文；空串 = 没错误
syncNow(): Promise<void>  // 手动同步，内部全 catch，不会抛
```

| `status` | 含义 | 界面建议 |
|---|---|---|
| `unauthenticated` | 没登录（或登录失效） | 不显示同步状态，或灰点「未登录」 |
| `unconfigured` | **历史遗留，现在已经不会出现**，忽略即可 | — |
| `idle` | 有未上传的改动，等防抖那 1.5 秒 | 「待同步」 |
| `syncing` | 正在上传 / 下载 | 「同步中…」转圈 |
| `synced` | 刚同步成功 | 「已同步」+ 上次时间 |
| `error` | 服务端拒绝 / 数据有问题 | 「同步出错」+ `lastError` + 「重试」按钮 |
| `offline` | 断网或连不上服务器 | 「离线，改动先存本地」（**不是错误**，不用红） |

⚠️ 两个坑：

1. **`isConfigured` 是历史遗留**（原来是"填了共享令牌没有"），现在恒等于 `status !== 'unconfigured'`。
   **判断登录请用 `useAuth().status`**，别用这个。
2. **`setToken` 已经废弃**（登录体系取代了共享令牌），现在是**空实现**，别接 UI。
   我下次清理会把它和 `isConfigured` 一起删掉。

### 错误码 → 中文文案对照表

**用法：不要判 code。**直接调用现成的函数：

```ts
import { authErrorMessage } from '../lib/auth'
catch (err) { setMsg(authErrorMessage(err)) }   // 永远得到一句能直接显示的中文
```

万一你需要按类型分支（比如"邀请码错"要高亮输入框），才用 `err.code`：

| `code` | 中文文案 | 建议交互 |
|---|---|---|
| `invalid-credentials` | 用户名或密码不对 | 清空密码框、聚焦密码 |
| `invalid-invite` | 邀请码无效，或已经被用过了 | 高亮邀请码框 |
| `username-taken` | 这个用户名已经被注册了，换一个试试 | 聚焦用户名框 |
| `forbidden` | 只有管理员能做这个操作 | 收起管理员入口 |
| `unauthorized` | 登录已失效，请重新登录 | 跳登录页 |
| `bad-request` | 服务端给的具体原因（如「工具数量 501 条，超过上限 500 条」）；没有则是「提交的内容不合规」 | 原样显示 |
| `not-found` | 要操作的记录已经不存在了 | 刷新列表 |
| `network` | 连不上服务器，请检查网络后重试 | 显示「重试」 |
| `server` | 服务器出错了（5xx），稍后再试 | 显示「重试」 |
| `bad-response` | 服务器返回的数据看不懂（等） | 当异常上报用 |
| `unknown` | 服务器返回 N | 原样显示 |
